# DevCage v0.7.0

Released: 2026-08-13

## Summary

Linux `devcage wrap` via bubblewrap, plus `devcage grok` fixes so nested Docker and `.env` deny work under `keys-first` on Linux.

## Highlights

- **`devcage wrap` on Linux:** uses `bwrap` when it is on `PATH` (same binds as macOS wrap; `--net none` → `--unshare-net`).
- **`devcage grok` + Docker:** generated `keys-first` leaves child network on. Grok's `restrict_network` seccomp also blocked `connect()` to `/var/run/docker.sock`, so `devcage run -p offline` failed inside the combined session. Hard no-network is still `offline` / `untrusted`.
- **Linux `.env` deny:** exact `.env` / `local.env` / `.env.local` (plus globs). Deny globs only match files that exist at launch; exact paths cover files created later. Generated recipes refresh on the next `devcage grok` / `init-grok`.
- **`devcage limits`** no longer overwrites or deletes a real project `.env`.
- Linux **release build** compiles (`seatbelt_enabled` is macOS-only).

## Install

```bash
./scripts/build.sh --release
./scripts/install.sh
devcage init-grok --force   # refresh keys-first recipes after upgrade
```

## Quick start

```bash
devcage grok                          # Grok (restart after upgrade)
devcage wrap -- claude                # any other agent (bwrap on Linux)
devcage wrap --net none -- cursor-agent
devcage run -p offline -- ./sketchy.sh
devcage limits
```

## Upgrade notes

Restart `devcage grok` after install so the new sandbox recipe applies. A session cannot change its sandbox in place.
